## 5. Standard Run Procedure

This is the canonical operator workflow as of commit `8272045`. Every new submission cycle should follow it.

### 5.1 Postmarket cases

```bash
cd faers-app
npm run build:headless
ELECTRON_RUN_AS_NODE=1 npx electron out/main/headless.js \
  --out-dir ../test/test_submission/from_app \
  ../test/test_submission/examples/cases/TC-XXX.json
```

Expect:
- Per-file `[route] ZZFDATST (CDER) N.1.4=ZZFDATST N.2.r.3=CDER` line — confirm before upload.
- End-of-run `=== SUBMISSION CHECKLIST ===` grouping by channel.
- Submission log entry written to `<userData>/submission-log.json` or `~/.faers-headless/submission-log.json` (override via `FAERS_SUBMISSION_LOG`).

Upload through the ESG portal **ZZFDATST** channel. Drop the ACK XML in `test/test_submission/acks/` keeping the FDA filename, then:

```bash
ELECTRON_RUN_AS_NODE=1 npx electron out/main/headless.js \
  --record-ack <batchUuid> --ack-id <ackId> --outcome <CA|CR|AE|AR|CA+AE|CR+AR>
```

### 5.2 IND / BA-BE cases

```bash
IND_ENROLLMENT_CONFIRMED=true \
ELECTRON_RUN_AS_NODE=1 npx electron out/main/headless.js \
  --out-dir ../test/test_submission/from_app/ind \
  ../test/test_submission/examples/cases/IND-TXX.json
```

Without `IND_ENROLLMENT_CONFIRMED=true` the run fails at `[ind-enrollment]` with the AEMSESUB instructions. Use `--skip-ind-enrollment` for offline regeneration only.

Expect:
- `[route] ZZFDATST_PREMKT (CDER_IND) N.1.4=ZZFDATST_PREMKT N.2.r.3=CDER_IND`
- Pass 1 may surface noise against the IND-T01 golden for cases that legitimately diverge (T04 no-NCT; T05 fatal). Use `--no-gate` until GAP-APP-004 follow-up is closed.

Upload through the ESG portal **ZZFDATST_PREMKT** channel. Same `--record-ack` flow afterward.

### 5.3 Failure-mode cheat sheet

| Symptom in ACK | Likely root cause | Where it's caught now |
|---|---|---|
| `File sent with AS2 header "CDER_IND" must have N.1.4 = "ZZFDATST_PREMKT"` | Wrong portal channel | `[route]` directive after `[write]` (GAP-SUB-001). |
| `Case Rejected as Message No and Sender Combination already Exists` | Re-uploading the same XML | `submissionLogService.hasBeenSubmitted` (GAP-SUB-002). |
| `please email AEMSESUB@fda.hhs.gov` portal email | IND enrollment missing | `[ind-enrollment]` pre-flight (GAP-SUB-003). |
| `D.9.1 has a value, D.9.3 must contain a value` | Missing autopsy on fatal case | Pass 3 fatal-case checks (GAP-IND-004 + GAP-XML-001 regression). |
| `FDA.C.5.5a is invalid for the Center` | Wrong receiver OR wrong IND number | `IND_POLICY.indNumber` registry guard in `xmlGeneratorService` (GAP-APP-003). |
| `effectiveTime` SAX parse error | HL7 v3 child-order violation | Generator emits `effectiveTime` before `value` (GAP-IND-003). |

## 6. Logging Future Runs

When you submit a new run, append a row to §3.1 (IND) or §3.2 (postmarket). Required columns: date, run label, package, batch UUID suffix (last 12 chars), channel, gates summary, result, ACK file id. Bump "Last updated" at the top of the file.

For new gap discoveries from a future ACK, follow the existing pattern:
1. Drop the ACK in `test/test_submission/acks/`.
2. Add a `docs/gaps/GAP-IND-NNN-….md` with the exact FDA error text and reproducible evidence.
3. Implement + commit referencing the gap doc id; promote `IND_POLICY` only on a confirmed CA+AE round-trip.
4. Add a row to §1 fix inventory.
5. If the gap is operator-process (channel, duplicate, enrollment, etc.) rather than XML content, mirror the GAP-SUB-* / GAP-CLI-* pattern: surface it in the headless CLI before submission rather than discovering it in an ACK.
