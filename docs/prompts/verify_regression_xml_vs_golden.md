# Claude Code Prompt — Verify Regression XMLs Against Golden Dataset

**Purpose:** Direct file-to-file comparison of every XML in
`test/test_submission/regression/xml/` against its matching golden in
`test/golden/<category>/xml/`. This is a spot-check that runs OUTSIDE
the headless CLI; it answers "do the committed regression XMLs match the
current golden on disk?" without re-running any generation.

**When to use:**
- After any golden regeneration (GAP-GOLDEN-001 pattern) to confirm the
  new golden and the committed regression XML agree
- After any generator code change before/after CI confirms 33/33
- As a quick sanity-check when the headless CLI is unavailable (e.g. on
  a machine without Electron)

---

## Background

### What lives where

| Path | Contents |
|---|---|
| `test/golden/<cat>/xml/*.xml` | FDA-accepted (or known-rejected) curated XMLs — the authoritative reference |
| `test/golden/<cat>/xml/*.ack` | FDA ACK files paired to each XML — never regenerated |
| `test/golden/<cat>/json/*.json` | JSON inputs that produce the golden XMLs via the headless CLI |
| `test/test_submission/regression/xml/*.xml` | XMLs generated by the most recent regression run and committed for inspection |
| `test/test_submission/regression/golden_regression_results.md` | Last regression run results |

### Coverage

36 scenarios total:
- 26 `postmarket/accepted` — CA+AA goldens
- 3 `postmarket/rejected` — CR+AR goldens (TC-A03, TC-A04, TC-A06)
- 7 `ind/accepted` — CA+AE goldens

3 scenarios have no JSON input and are always SKIPPED by the regression
test: TC-A06-ethnicity-ni, TC-F02-comboproduct, TC-F04-ich-rpttype-2.
They DO have XMLs in the golden and may or may not have a file in
`regression/xml/` depending on how the regression run was configured.

### Normalization rules

These fields differ legitimately between any two generator runs and must
be excluded before diffing:

| Field | Rule |
|---|---|
| `id/@root` = UUID4 | Volatile per-generation — blank before diff |
| `id/@extension` = UUID4 or BatchID | Volatile — blank before diff |
| `id` under MCCI_IN200100UV01 with OID `.3.22` | Batch UUID — blank |
| `id` under PORR_IN049016UV with OID `.3.1` | Message UUID — blank |
| `id` under `investigationEvent` with OID `.3.1` or `.3.2` | Case/worldwide IDs — blank |
| `creationTime/@value` | Generation timestamp — blank |
| `availabilityTime/@value` | Generation timestamp — blank |
| `controlActProcess/effectiveTime/@value` | Run timestamp — blank |

The `golden_regression_test.py` normalizer at lines 222–288 already implements
all of these. Any direct comparison script must apply the same rules.

**Key finding (2026-05-09):** Per-observation `<id>` elements inside
`adverseEventAssessment/…/subjectOf2/observation` use a bare UUID4 as
`@root` (no OID namespace). The regression test's line 271-278 already
blanks these via the generic `UUID_RE.match(root_attr)` check. A naive
comparison that only checks `@extension` will produce false-positive
STRUCTURAL DIFF for every scenario (33 spurious diffs per run), masking
real issues.

## Task: run the direct comparison

**Step 1 — write the comparison script** to a temp location and run it:

```bash
python3 - << 'PY'
"""
Direct comparison: test/test_submission/regression/xml/ vs test/golden/<cat>/xml/
Apply the same normalization as golden_regression_test.py (UUID4-in-root blanking, etc.)
"""
import re
from pathlib import Path
from lxml import etree as ET

REPO = Path(__file__).resolve().parents[3] if "__file__" in dir() else Path(".")
# Run from repo root:
REPO = Path(".").resolve()
REG_DIR = REPO / "test/test_submission/regression/xml"
GOLDEN_DIRS = {
    "postmarket/accepted": REPO / "test/golden/postmarket/accepted/xml",
    "postmarket/rejected": REPO / "test/golden/postmarket/rejected/xml",
    "ind/accepted":        REPO / "test/golden/ind/accepted/xml",
}

UUID_RE  = re.compile(r"^[0-9a-f]{8}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{12}$", re.I)
BATCH_RE = re.compile(r"^DeepQuence(Test|Prod)?-\d{8}-[0-9a-f\-]{36}$", re.I)
EXCLUDED_IDS_BY_OID = {
    ("MCCI_IN200100UV01", "2.16.840.1.113883.3.989.2.1.3.22"),
    ("PORR_IN049016UV",   "2.16.840.1.113883.3.989.2.1.3.1"),
    ("investigationEvent","2.16.840.1.113883.3.989.2.1.3.1"),
    ("investigationEvent","2.16.840.1.113883.3.989.2.1.3.2"),
}
EXCLUDED_TAGS     = {"creationTime", "availabilityTime"}
EXCLUDED_ET_PARENTS = {"controlActProcess"}

def local(tag): return tag.split("}")[-1] if "}" in tag else tag

def normalize(root_el):
    """Blank volatile attributes in-place (mirrors golden_regression_test.py)."""
    for el in root_el.iter():
        tag = local(el.tag)
        # Timestamp tags
        if tag in EXCLUDED_TAGS:
            if "value" in el.attrib: el.set("value", "__VOLATILE__")
        # controlActProcess/effectiveTime
        if tag == "effectiveTime":
            p = el.getparent()
            if p is not None and local(p.tag) in EXCLUDED_ET_PARENTS:
                if "value" in el.attrib: el.set("value", "__VOLATILE__")
        # id elements
        if tag == "id":
            p = el.getparent()
            pl = local(p.tag) if p is not None else ""
            root_attr = el.get("root", "")
            # Named-OID exclusions → blank @extension
            if (pl, root_attr) in EXCLUDED_IDS_BY_OID:
                if "extension" in el.attrib: el.set("extension", "__VOLATILE__")
            # UUID4 or BatchID anywhere in @root or @extension → blank both
            for attr in ("root", "extension"):
                v = el.get(attr, "")
                if v and (UUID_RE.match(v) or BATCH_RE.match(v)):
                    el.set(attr, f"__VOLATILE_{attr.upper()}__")

def canon(el): return ET.tostring(el, method="c14n")

def find_golden(scenario):
    for cat, gdir in GOLDEN_DIRS.items():
        p = gdir / f"{scenario}.xml"
        if p.exists(): return cat, p
    return None

match, diff, missing = [], [], []
for reg_path in sorted(REG_DIR.glob("*.xml")):
    s = reg_path.stem
    found = find_golden(s)
    if not found: missing.append(s); continue
    cat, golden_path = found
    g = ET.parse(str(golden_path)).getroot()
    r = ET.parse(str(reg_path)).getroot()
    normalize(g); normalize(r)
    if canon(g) == canon(r): match.append((s, cat))
    else: diff.append((s, cat))

print(f"MATCH  : {len(match)}")
print(f"DIFF   : {len(diff)}")
print(f"MISSING: {len(missing)}")
if diff:
    print("\n## DIFFS:")
    for s, cat in diff: print(f"  - {s} [{cat}]")
if missing:
    print("\n## No golden found for:")
    for s in missing: print(f"  - {s}")
if not diff and not missing:
    print("\nAll regression XMLs match the golden dataset exactly (after normalization).")
PY
```

Run from repo root:


## What a DIFF means

If the comparison finds a DIFF after a generator commit, classify it:

| Diff type | Example | Action |
|---|---|---|
| Child count change | `substanceAdministration child_count golden=5 reg=6` | New emission — either a generator regression OR a valid new emission that needs golden regen |
| Coded value change | `@code golden=hospitalization reg=otherMedicallyImportant` | Content change — check if the generator is correct; if golden is stale, regen |
| UUID4 in non-volatile field | `@root golden=<uuid> reg=<uuid>` (non-observation id) | Normalization gap — add the field to the exclusion list |
| Structural reorder | `tag golden=X reg=Y` at same position | Element order change — check generator commit |

Do NOT regen the golden unless the generator change is intentional and the
new output passes lint (60/60) and the content is FDA-rule-compliant.
Follow the promotion convention in `SUBMISSION_CAMPAIGN_REPORT.md §1.5`.
